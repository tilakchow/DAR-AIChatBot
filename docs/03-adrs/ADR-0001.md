# ADR-0001: Retrieval-Augmented Generation (RAG) Architecture

- **Status:** Accepted
- **Date:** 2026-11-18
- **Deciders:** Tilak (Lead), AI Assistant
- **Consulted:** Assignment Brief, Project Plan Section 4

## Context and Problem Statement

The assignment requires building an AI chatbot capable of answering questions about DarGlobal property developments and Wasalt real estate listings.
Real estate data changes dynamically (unit availability, construction phases, pricing), and general-purpose LLMs lack access to proprietary, current listings from `darglobal.co.uk` and `wasalt.sa`.

## Considered Options

1. **Fine-Tuning:** Retrain/fine-tune an open-source model weights on scraped listings.
   - *Drawback:* Expensive, slow, risks severe hallucination of numbers, cannot cite exact URLs, requires retraining on every scrape update.
2. **Long-Context Prompt Stuffing:** Put the entire scraped dataset directly in the system prompt.
   - *Drawback:* Exceeds free-tier token limits (context windows on free models are constrained), high latency, costly.
3. **Retrieval-Augmented Generation (RAG):** Index scraped text and retrieve only the top relevant chunks to ground the LLM's response.

## Decision

We adopt **Option 3: Retrieval-Augmented Generation (RAG)**.

### Rationale
- Keeps answers grounded in verified scraped passages.
- Enables precise `[n]` citations back to original URLs.
- Allows continuous data updates without retraining or fine-tuning models.
- Operates within free-tier context and token constraints.

## Consequences
- Requires a data collection, cleaning, and indexing pipeline (Milestones M2 and M3).
- Requires guardrails against untrusted context and prompt injection.
