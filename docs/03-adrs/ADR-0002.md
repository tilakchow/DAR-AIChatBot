# ADR-0002: Hybrid Retrieval Index Architecture (BM25 + Dense Vectors)

- **Status:** Accepted
- **Date:** 2026-11-18
- **Deciders:** Tilak (Lead), AI Assistant
- **Consulted:** DAR-18, DAR-20, Risk R7

## Context and Problem Statement

The chatbot must retrieve relevant real estate facts and listing information for queries in both English and Arabic. Real estate queries frequently include:
1. Exact keyword identifiers: project names (e.g., "The Astera", "Trump Tower Jeddah"), developer names ("DarGlobal"), district names ("Al Narjis"), and specific price points.
2. Semantic / conceptual expressions: "sea view villas", "beachfront luxury", "affordable rental flat", and Arabic equivalents ("شقق قريبة من المطار", "فلل فاخرة").

Dense-only retrieval often misses exact project codes and proper nouns, while sparse keyword-only retrieval (BM25) fails on paraphrased and cross-lingual semantic matches.

## Decision

We adopt a **Hybrid Search Index** combining:
1. **BM25 (Best Matching 25):** Tokenized keyword index with language-specific tokenization (English and Arabic character normalization) for precision on proper nouns, project names, and numeric filters.
2. **Dense Vector Embeddings:** Multilingual sentence embeddings for semantic similarity across English and Arabic.
3. **Reciprocal Rank Fusion (RRF):** Merging rank lists from both systems with parameter $k=60$.
4. **Graceful Degradation:** If dense embeddings cannot be computed or model fails to load in constrained environments, the retriever automatically falls back to BM25-only mode without crashing.

## Index Storage
The processed chunks and BM25 inverted index are stored in `data/processed/index.json` and embedded vectors in `data/processed/embeddings.npy` or serialized vector store. This self-contained file is baked directly into the Docker container during the build stage (DAR-27) for zero-dependency instant startup.

## Consequences
- **Positive:** Maximum recall and precision on both exact project titles and semantic queries; zero latency during container cold starts; robust offline fallback.
- **Negative:** Dual index requires a processing step at build time.
