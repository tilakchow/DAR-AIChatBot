# ADR-0003: OpenRouter Model Selection & Cascade Fallback Strategy

- **Status:** Accepted
- **Date:** 2026-11-18
- **Deciders:** Tilak (Lead), AI Assistant
- **Consulted:** DAR-4, DAR-22, Risk R3, Risk R4

## Context and Problem Statement

The assignment mandates using a **free model** available on OpenRouter.
Free tier models on OpenRouter carry strict constraints:
1. High volatility: free model endpoints are frequently congested, throttled, or deprecated without advance notice.
2. Rate limits: 20 requests per minute and 50 requests per day for zero-credit accounts.
3. Reliability: depending on a single free model causes immediate downtime if that endpoint experiences peak traffic.

## Decision

We adopt a **Cascade Fallback Strategy** implemented in `OpenRouterClient`:
1. **Primary Model:** `nvidia/nemotron-3.5-super-vl:free` (strong reasoning, instruction following, and multilingual support).
2. **First Fallback:** `meta-llama/llama-3.3-70b-instruct:free` (robust general capability and citation adherence).
3. **Second Fallback:** `google/gemini-2.0-flash-exp:free` (fast low-latency completion).
4. **Final Fallback:** `openrouter/free` (OpenRouter's dynamic free-model load balancer).

## Quota Protection Architecture
To protect the daily free quota:
1. **Input Length Cap:** Max 1,000 characters to prevent token exhaustion.
2. **Early Refusal:** Out-of-scope and prompt-injection requests are rejected before making an LLM API call.
3. **Sliding-Window IP Rate Limiter:** Max 15 requests/minute per client IP.
4. **Answer Cache:** Identical queries are served from memory for 1 hour without calling OpenRouter.

## Consequences
- Guaranteed uptime even if individual free models face intermittent 429 or 5xx errors.
- Every chat response logs and returns the exact `model_used` attribute.
